# 검증 기록

최신 검증일: **2026-09-30 KST**, Orchestra **1.1.0**. 대상: Ubuntu WSL, Codex CLI **0.159.2**, Python **3.12.3**. 아래 실제 하위 작업 시험은 앞선 2026-09-28 기록이며 CLI **0.157.1**에서 수행했습니다.

이 문서는 공개 배포본의 재현 가능한 시험과 개발 중 수행한 실제 모델 시험을 구분합니다. 개인 작업 경로, 세션 식별자, 원시 실행 로그는 배포하지 않습니다. 실제 모델 시험은 아래에 범위를 요약한 개발자 관측이며, 저장소만으로 동일한 호스트 환경을 재현할 수 있다는 주장은 아닙니다.

## 공개 배포본에서 재현 가능한 시험

```bash
python3 -m unittest discover -s tests -v
```

**81개 시험 통과.** 네트워크나 유료 모델 호출 없이 Python 표준 라이브러리로 실행합니다. 배포 버전 확인의 네트워크 응답은 시험에서 대체합니다.

| 영역 | 시험 내용 |
|---|---|
| 정책 | 후보 모델, 모델별 추론 범위, 총괄 강도 상한, 선택 변경, 입력 형식 |
| 슬롯 예약 | 5/20 상한, 마지막 슬롯 경쟁, 중복 요청, 생성 응답 유실 |
| 작업 상태 | 의존 실패 전파, 재시도 상한, 완료·취소 이후 늦은 응답, 검토 독립성 |
| 파일 소유권 | 겹치는 쓰기 범위, Windows/WSL 경로 별칭 |
| 증거·정리 | 요청값과 실제값 구분, 종료 확인 없는 슬롯 유지, 정리 미확인 보고 |
| 패키징 | 13개 파일 일치, 기존 설치 보존, ZIP 경로·구성원·CRC |
| 모델 동기화 | 새 버전 발견, 숫자 기준 세대 순서, 목록에서 사라진 모델·숨김·종료 처리, 도구별 지원 범위, 목록 변경 뒤 재검사 |
| 업데이트 알림 | 새 배포·동일 버전·로컬 선행 버전, 연결 실패·잘못된 응답 처리, 자동 설치 없음 |
| 호환성 진단 | 누락·불일치·미검증 설정을 호환 성공으로 오인하지 않는지 확인 |

`test_native.py`의 일부 이름은 초기 엄격 모드 진단의 이력을 반영합니다. 진단 함수의 결과를 시험하며, 현재 스킬이 후크로 네이티브 생성을 강제 차단한다는 의미가 아닙니다.

최초 공개용 정리에서는 스킬 본체의 10개 파일을 보존했습니다. 이번 1.1.0은 모델 발견·추론 범위·종료일 확인과 업데이트 알림을 추가해 스킬 패키지가 13개 파일입니다.

## 1.1.0 모델 변화 대응 확인

기존 설치본에서 `gpt-6.1-sol`이 후보에 없고 총괄 선택도 `LEADER_SELECTION_INVALID`로 거부되는 문제를 재현했습니다. 고정된 7개 모델 목록을 제거한 뒤 실제 `codex debug models` 응답으로 새 Sol 세대를 확인했습니다.

- 새 모델은 현재 목록과 에이전트 도구의 지원 범위에 함께 있어야 배정할 수 있습니다.
- 알려진 계열의 세대는 숫자로 비교합니다. 가격·성능을 측정한 순위는 아닙니다.
- 종료 시각이 지나면 목록에 남은 모델도 제외하는 경계를 모의 시각으로 시험했습니다. 앞으로의 서비스 종료를 실제로 관측한 결과는 아닙니다.
- 모델 목록이 바뀌면 준비된 요청을 다시 검사하며, 응답이 유실된 기존 예약은 새 모델 생성 없이 조회할 수 있습니다.
- 새 배포 버전 알림과 연결 실패 처리를 시험했습니다. 코드를 자동 설치하지 않습니다.

이번 업데이트에서 실제 네이티브 하위 작업 시험을 반복하지는 않았습니다. 아래의 두 작업 기록과 5/20 동시 실행 미검증 범위는 그대로 적용됩니다.

## 실제 설치본 시험에서 확인한 내용

총괄 **Sol / High**, 상한 **5명**으로 준비한 시험 세션에서 실제 작업은 두 개로 제한했습니다.

| 실제 도구에 요청한 배정 | 작업 | 관측 결과 |
|---|---|---|
| `gpt-6-sol / medium` | 작은 합계 함수 오류 수정 | 코드 수정, 빈 입력·혼합 입력 시험 통과; 별도 재실행 확인 |
| `gpt-6-luna / medium` | 제공 자료와 CAD 목록 검토 | 자료 노트 작성, 단위 불명·CAD 파일 부재·실측 미제공 명시 |

설치 스킬 목록 인식, 명시적 호출로 스킬 읽기, 보조 도구 사용, 네이티브 생성 요청 및 결과 반환을 확인했습니다. 실제 CAD 파일의 열기·편집·저장이나 외부 연구 논문 검색은 이 시험에 포함하지 않았습니다.

최종 유효 모델·추론 강도는 생성 도구 응답에서 노출하지 않아 `null` / `unverified`로 보존했습니다. 요청한 값을 실제값으로 간주하지 않았습니다.

두 하위 작업은 네이티브 목록에서 `completed`로 나타났습니다. 그러나 사용 가능한 interrupt 도구는 후속 작업이 가능한 에이전트를 남기고, 별도 close 도구는 없어 전체 종료는 확인하지 못했습니다. 기록은 `IDLE`, 최종 정리 상태는 **`CLEANUP_REQUIRED`**입니다.

## 검토 뒤 수정한 회귀 결함

독립 검토에서 찾은 다음 세 항목은 실패를 재현한 뒤 수정했습니다.

1. 중복·늦은 생성 응답이 완료·취소 등 기존 상태를 실행 중으로 되돌리는 문제.
2. 여러 단계 의존 관계의 실패가 마지막 작업까지 전파되지 않는 문제.
3. 객체가 아닌 `check.request`에서 구조화된 거절 대신 예외가 발생하는 문제.

수정 후 58개 로컬 시험을 통과했고 원본·설치본·ZIP의 10개 파일을 대조했습니다. 최종 설치본 보조 도구로 실제 시험 DB의 보고서도 다시 생성했습니다. **수정 이후 유료 모델 시험을 반복하지는 않았습니다.**

## 확인하지 않은 범위

- 실제 5명 또는 20명의 동시 모델 실행과 처리량·비용·성능 비교.
- 모든 후보 모델의 제공 여부와 모든 계정·Codex 버전의 호환성.
- 생성 도구가 공개하지 않는 최종 유효 모델·추론 강도.
- close 기능이 없는 도구 환경에서의 전체 하위 에이전트 완전 종료.
- 외부 UI의 총괄 설정 변경 자동 탐지와 런타임 오류에 대한 강제 차단.

해당 Codex 버전의 후크 오류 처리 관측 때문에 이 버전은 **스킬의 운영 규칙과 검사**를 사용합니다. 자세한 호환성 조건과 원본 코드 참조는 [native-compatibility.md](../orchestra/references/native-compatibility.md)에 있습니다. 이 스킬은 후크를 설치하지 않습니다.
