# Orchestra 사용 안내

Orchestra는 VS Code의 WSL 터미널에서 실행하는 Codex에 사용하는 스킬이다. 사용자가 선택한 총괄 모델을 유지하면서 하위 작업의 모델과 추론 강도를 자동으로 배정한다.

## 호출

```text
$orchestra 5 이 프로젝트의 오류를 조사하고 수정한 뒤 결과를 검토해줘.
```

숫자는 **총괄을 제외한 하위 에이전트의 최대 동시 실행 수**다. 5~20 사이에서 지정하고 생략하면 5다. 자문역과 검토자도 이 수에 포함한다. 항상 해당 인원을 채우는 것이 아니라 필요한 만큼만 구성한다.

다른 분야도 같은 형식으로 요청한다.

```text
$orchestra 8 이 CAD 자료를 정리하고 파일 간 관계와 검토가 필요한 부분을 확인해줘.
$orchestra 10 이 연구 자료들의 근거를 대조하고 실험 계획 초안을 만들어줘.
```

스킬은 필요한 도구나 원문이 없는 작업을 실제로 검증했다고 보고하지 않는다.

## 모델 선택 방식

총괄 모델과 추론 강도는 사용자가 정한다. 하위 작업은 명확성, 복잡성, 오류 영향, 검증 가능성, 도구·자료 준비 상태에 따라 배정한다.

| 작업 예시 | 기본 후보 |
|---|---|
| 단순 자료 추출·파일 목록·명확한 작은 수정 | Luna / Low 또는 Medium |
| 일반 구현·여러 단계의 분석 | Sol / Medium 또는 High |
| 중요한 설계 판단·어려운 검토 | Astra / High |

총괄이 Sol / High여도 자문역에 Astra / High를 배정할 수 있다. 총괄이 Astra / Low라면 모든 하위 작업도 Low 안에서 배정한다. 실제 사용 가능한 모델·추론 조합만 사용하며, 위 표는 성능 보장이 아닌 시작 기준이다.

현재 총괄 선택을 환경에서 읽지 못하면 필요한 값만 확인한다. 이미 대화에서 확인한 선택을 반복해서 묻지 않도록 했다. 실행 도중 모델·추론 강도를 바꾸었다면 스킬에도 알려 새 배정에 반영하게 한다.

## 설치와 실행 환경

- WSL 설치 위치: `~/.agents/skills/orchestra/`
- 설치: 저장소 루트에서 `python3 tools/install_orchestra.py`. 기존 동명 스킬은 백업한다.
- ZIP 생성: `python3 tools/install_orchestra.py --zip dist/orchestra.zip`.
- 사용자 진입점: `SKILL.md`. 보조 스크립트는 스킬 내부에서 검사·기록에 사용한다.
- 별도 앱·상주 서비스·모델 API 키가 필요하지 않으며 OMC·OMX에도 의존하지 않는다.
- 일반 대화에서 자동으로 팀을 시작하지 않는 명시적 호출 방식이다.

이미 열려 있는 세션에서 새 스킬이 보이지 않으면 새 WSL Codex 세션에서 호출한다. 설치 여부와 목록 표시 여부는 별개이므로, 표시 문제만으로 재설치하거나 기존 설정을 삭제하지 않는다.

Codex 세션 자체의 에이전트 제한이 요청한 수보다 작으면 그 세션에서 해당 인원으로 진행할 수 없다. 예를 들어 새 세션을 20명 상한 설정으로 준비하려면 다음과 같이 시작할 수 있다.

```bash
codex -c 'agents.enabled=true' -c 'agents.max_concurrent_threads_per_session=20' -c 'agents.max_threads=20'
```

이 명령은 모델·추론 강도를 지정하거나 전역 설정 파일을 변경하지 않는다. 새 세션에서 의도한 총괄 모델을 선택한 뒤 스킬을 호출한다. 현재 실행 중인 세션의 제한을 바꾸는 명령은 아니다. 실제 실행 가능 수는 해당 호스트의 제한도 따른다.

## 결과와 보장 범위

작업별 기록은 기본적으로 프로젝트의 `.orchestra/<실행 ID>/`에 보존한다. 배정 이유, 요청한 모델·강도, 확인된 실제값, 작업 결과, 검토와 정리 상태를 구분한다.

이 버전은 **스킬의 운영 규칙과 검사로 관리하는 방식**이다. Codex 내부 오류까지 포함한 강제 차단은 보장하지 않는다. 5~20 설정·로컬 예약 검사와 실제 20개 모델의 동시 실행은 서로 다른 검증 항목이다.

종료 확인이 안 되는 환경에서는 산출물이 완성되어도 `CLEANUP_REQUIRED`와 남은 식별자를 보고한다. 에이전트가 답변했다는 이유만으로 종료 확인이나 자리 반환을 완료했다고 처리하지 않는다.

구체적인 설치본 시험과 확인된 한계는 [검증 보고서](validation.md)를 따른다.
